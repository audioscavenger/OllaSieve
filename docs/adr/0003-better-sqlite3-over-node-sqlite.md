# better-sqlite3 over node:sqlite

OllaSieve uses better-sqlite3 (pinned to v12, the first series with a Node 24 win32-x64 prebuilt binary) as its SQLite driver instead of Node's built-in `node:sqlite` (DatabaseSync). Both provide the same synchronous API the codebase relies on (`prepare().run/all/get`, `exec`, `pragma`, `transaction`), so the decision is about operational risk, not capability. better-sqlite3 is a mature, widely used native module whose prebuilt binaries are fetched by prebuild-install at install time, so it installs cleanly on any platform without a compiler toolchain or Python; node:sqlite is newer, ships no `transaction()` helper, and still carries `Experimental` baggage on some Node 22 lines. The trade-off is one extra native dependency that must track Node ABI releases: v11, originally pinned, predates Node 24 and has no Node 24 prebuilt, which broke `npm install` on this machine (no Python for node-gyp) and forced the v12 bump. node:sqlite was rejected because it would require rewriting `src/db.js` and the `db.transaction()` call in `src/cap-ledger-records.js` to explicit `BEGIN/COMMIT`, for a dependency we would have to maintain and debug ourselves; revisiting if better-sqlite3 prebuilds stop tracking a Node major we depend on.
